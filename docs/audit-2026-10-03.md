# Repository audit — 3 October 2026

The audit covered channel ingestion, transcript correction, character and
phoneme alignment, corpus installation/export, the HTTP API and editor,
generation jobs, YTPMV rendering, Matrix integration, frontend state, and
container startup. It produced code fixes and regression fixtures, plus the
remaining priorities below. Changes are in the working tree; no running
deployment or shared Python/CUDA environment was updated.

Building a channel corpus uses pretrained transcription/alignment models.
The fixes improve which recordings and labels enter the corpus, how their
boundaries are measured, and how generation uses them. They do not retrain
model weights, and no measured improvement in transcription word error rate
is claimed.

## Security and data integrity

| Finding | Impact before the fix | Implemented change and evidence |
| --- | --- | --- |
| Public operator API | Network clients could edit, replace and generate without a login. | Compose and Docker examples now bind to localhost. Remote access still requires an authenticated proxy; this is a deployment safeguard, not application authentication. |
| Webhook SSRF and DNS changes | User-supplied callback URLs could reach internal addresses or change their destination between validation and connection. | Validate every resolved address at admission and delivery; connect to validated numeric addresses; preserve HTTPS certificate/SNI checks; refuse redirects and ambiguous Unicode hostnames. Connections have finite timeouts and callback concurrency is bounded. |
| Upload parsing before validation | MIDI could receive the bundle-sized body allowance; multipart spooling happened before endpoint checks. | Route-specific limits apply before parsing, including chunked requests. File routes require multipart encoding; other request bodies retain a small limit. |
| Unsafe bundle extraction | Links, traversal, Windows alternate streams/devices and unexpected members could escape or corrupt an installation. | Extract regular files/directories from an allow-list into private staging; reject nonportable/duplicate names and links; cap total extracted bytes and members; validate SQLite tables and integrity before activation. |
| Destructive forced import | Bad input could replace the old corpus before it had been validated. | Swap a validated directory atomically, restore on failed swap, and retain the previous directory under `corpora/.backups/`. Loose unpack preserves unrelated files and backs up replaced members. |
| Corpus changes during work | A running job, edit or dictionary lookup could use another selected voice; forced replacement could race admitted writes/alignment. | Capture a corpus context for requests, jobs and alignment threads; scope dictionaries and recipes by corpus; reserve maintenance against writes and jobs. `X-Corpus` rejects stale writes with 409. |
| Stale dependent data after re-transcription | Old alignment rows, ratings and recipe clip IDs could refer to newly assigned words. | Replace source clips transactionally, clear only their dependent rows/caches, remap unambiguous recipe pins, and release ambiguous pins. Refuse hand-edited sources without `--replace-edited`; abort on concurrent clip or source-file changes. |
| Lost SQLite WAL writes | Container seeding copied the main DB directly; legacy migration ignored failed checkpoints before deleting WAL files. | Seed through SQLite backup into staging, include pronunciation overrides, and activate after validation. Migration aborts on a busy checkpoint before moving files. It requires the app to be stopped. |
| Imported identifiers used as filenames | A video ID with path syntax could write reference/caption files outside their directory. | Preserve normal flat IDs; hash unsafe identifiers into confined artifact names. |
| Executable edge-check cache | `pickle.load` read a predictable shared temporary cache. | Remove that cache and reuse the validated character-alignment cache. |
| Stored HTML in editor views | Imported words, source labels or diagnostics could become markup. | Escape dynamic text, including diagnostic/error views; regression and browser tests confirm hostile labels remain literal text. |
| Matrix media and shutdown | Media was buffered without a reliable cap; cancelled jobs could remain nonterminal; background tasks could outlive shutdown. | Stream bounded downloads/uploads through the configured homeserver, validate MXC URLs, refuse redirects, apply finite timeouts, preserve authorized MIDI ownership, bound command tasks and drain them during shutdown. |

The webhook controls follow the separation of destination validation and
connection described in the [OWASP SSRF prevention guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html).
Tests use mocked callbacks and Matrix clients; they send no messages to third
parties.

## Optimization and accuracy fixes

| Area | Implemented improvement |
| --- | --- |
| Channel resume | Deduplicate video IDs, verify usable existing recordings, and apply the requested total ingestion budget across wrapper stages. |
| Transcription | Share model/language/prompt settings across build, ingest and re-transcription. Reject empty transcripts and invalid/nonfinite timestamps. |
| Alignment | Correct CTC delimiter/target handling, log-probability input, model evaluation and repeated-token handling. Preserve numeric/ordinal word ranges and hand edits. Constrain edges against neighbors and recording end. |
| Expensive stages | Separate transcription and alignment process lifetimes; persist alignment checkpoints and reuse source/window-sensitive character caches. |
| Media/cache identity | Use source path/stat fingerprints and exact segment/neighbor metadata to prevent stale reuse across voices and detect recording replacements. Validate mixed resolutions, rotation and audio formats. Stat-based identity is not a cryptographic content check. |
| Queue resources | Synchronize initial worker startup, reserve batches atomically, roll back failed reservations, and physically remove cancelled entries. Finished history remains bounded. |
| Cancellation | Terminate and reap FFmpeg, including blocked raw-video writes; close mappings before removing stem directories; remove partial output on failure/cancellation. |
| Retained memory | Apply a 128 MiB global decoded-frame retention budget and an 8 MiB note-cache budget per voice. These limits do not bound active render buffers or total process memory. |
| Repeated pitch work | Cache a voice's peak selection. In the focused benchmark, 5,000 selections fell from 0.9157 s to 0.0003 s. The sustained-audio fixture stayed byte-identical; this is not a whole-render speedup measurement. |
| Recommendation cache | Serialize cache writes with unique atomic temporary files; cancellation clears pending measurements and active FFmpeg decodes. |
| Caption verification | Split multiword caption segments into words, validate timing, recover corrupt caches, and bound downloaded caption data. This avoids false conflicts such as treating “hot food” as “hotfood.” |

## Quality of life

Editor and splice requests now discard stale responses after changing a word,
source, selection or corpus. Save/delete/settings failures restore usable
controls. Clip choices work from the keyboard. Generation history retains its
corpus, and unknown/other-corpus history cannot vote on or edit unrelated IDs.

The spectrogram now measures audio with a bounded STFT instead of drawing
volume-shaped synthetic frequency bands. It is requested only when opened,
with bounded dimensions/window length and a source-sensitive LRU. Synthetic
tone/silence tests verify the measured frequencies and silence; browser
screenshots use synthetic media and contain no personal corpus content.

CLI documentation now explains re-transcription safeguards, retained import
backups, localhost deployment, and corpus-pinned API requests. CI includes
the new Python/Node regressions and installs FFmpeg before render checks.

dependency tree: 85 packages initially, with advisory matches for six package
names. Duplicate GHSA/PYSEC entries are not counted as separate bugs.

Compatible minimum requirements now include FastAPI 0.136.3, Starlette 1.3.1,
AnyIO 4.14.2, urllib3 2.8.0 and NLTK 3.10.3. The new floors were resolved and
tested in an isolated target directory. Existing shared and CUDA environments
remain unchanged, so a rebuilt environment/image is needed to apply them.

The isolated patched overlay scan checked 87 packages. Remaining matches were
the three qualified NLTK, PyTorch and setuptools cases above. This scan covered
that Python dependency tree; it did not certify the deployed container,
system FFmpeg libraries, every optional feature or all GPU environments.

## Remaining priorities

1. **Authenticate remote HTTP access.** Keep localhost binding or an authenticated
   proxy. If this becomes a shared service, add application identity and
   authorization for editing, import/export, settings and generation.
2. **Bound work outside the main queue.** Preview, envelope and analysis calls
   can still create concurrent work. Use a shared admission budget and bounded
   per-client rate limits with cancellation; avoid holding corpus locks during
   encoding or network I/O.
3. **Budget disk usage.** Output retention is age-based, without an aggregate
   quota. Backups also intentionally persist. Balanced rendering allocates a
   full-song float16 stem per playing part: 400 parts × 900 s × 44.1 kHz ×
   2 bytes is about 29.6 GiB of logical stem data. Use span-sized/sparse stems
   and preflight free-space checks, then verify loudness/audio equivalence.
4. **Measure accuracy before tuning further.** Build a representative manually
   labeled evaluation set across voices, noise levels and short consonants.
   Record word error rate, onset/offset median and 95th-percentile error, and
   listening judgments for final-phone truncation and splices. Compare model,
   prompt, VAD and confidence thresholds on the same set.
5. **Improve pronunciation coverage.** Preserve stress and pronunciation
   alternatives, consider confidence/VAD review queues, and evaluate acoustic
   tail validation. These require measured evidence rather than broad changes
   to all boundaries.
6. **Profile longer builds.** Inference batching and decoded-audio reuse may
   help, but need GPU-memory and throughput measurements on representative
   long recordings. The peak-selection microbenchmark alone cannot predict
   their benefit.
7. **Verify the deployed artifact.** Rebuild with patched dependencies; check
   authenticated proxy/forwarded-header configuration and live service access.
   Container image building and a deployed penetration test were outside this
   local verification pass.

## Verification record

- All 45 standalone Python test scripts excluding the network/GPU end-to-end
  script passed in the broad local run, including real FFmpeg media/render
  fixtures. New security cases were then rerun against the patched overlay.
- Seven suites passed against the exact patched dependency floors: security
  API (21 tests), hardening, editor audio (7), numeric alignment (10), tokenizer
  (46 cases), corpus context (4), and export (8). Metadata had no conflicts.
- Node regressions passed for script parsing, asynchronous response races,
  failure recovery, history provenance and stored HTML escaping.
- Headless Chromium passed the synthetic editor/splice tone, source race,
  hostile-label/diagnostic, keyboard selection, history, settings-failure and
  YTPMV-startup checks. Screenshots are under `output/frontend-smoke/`.
- The real CUDA end-to-end run downloaded a 63-second recording, stored and
  aligned 66 clips, refined 66/66, then generated playable 2-word (1.32 s) and
  5-word (2.40 s) videos. Pipeline completion was about 57 s; wrapper elapsed
  time was 58.95 s. It used a temporary corpus and cached models.
- Byte compilation, workflow YAML parsing and `git diff --check` passed. No rebuild or re-ingestion of an installed corpus
  was performed. The pre-existing modified demo database was left in place.

This is a code and local-behavior audit, with qualified dependency triage. It
does not establish a new model accuracy score or certify an unauthenticated
deployment as secure.
